# Установка поверх действующего MediaCMS

## Важно

Не создавать новый MediaCMS и не заменять работающие PostgreSQL, Redis, Celery, FFmpeg, Whisper, Caddy и AI Gateway. Интеграция выполняется только после резервной копии и в тестовой среде.

## 1. Резервная копия

Сохранить:

- PostgreSQL;
- пользовательские медиа;
- `cms/settings.py`, `cms/urls.py`, Caddyfile и compose-файлы;
- шаблоны авторизации;
- текущий frontend;
- `.env` в зашифрованном виде, не помещая его в публичный архив.

## 2. Frontend

Папка верхнего уровня содержит самостоятельный статический прототип. Для MediaCMS его нужно перенести в фактический механизм шаблонов/статики текущего релиза. Не заменять всё дерево вслепую: сначала сопоставить маршруты страниц и сборку существующего frontend.

## 3. Django-мост

1. Скопировать `zhuravli_bridge` в корень Django-проекта рядом с другими приложениями.
2. Добавить `zhuravli_bridge` в `INSTALLED_APPS`.
3. В `cms/urls.py` подключить:

```python
path("api/portal/", include("zhuravli_bridge.urls")),
```

4. Добавить `httpx`, `python-magic`, `clamd`, `django-redis` в зависимости после проверки текущего менеджера пакетов.
5. Перенести нужные параметры из `security/django_security_settings.py` в существующие settings, не дублируя уже заданные значения.
6. Настроить серверные переменные из `deploy/.env.security.example`; токен AI не выводить в терминал и не коммитить.

## 4. Загрузка файлов

`security/upload_validation.py` — готовая строгая проверка, но её нужно вызвать в существующем обработчике загрузки MediaCMS **до** перемещения файла в публичное хранилище и до FFmpeg. Карантинное хранилище должно быть отдельным и не раздаваться Caddy/Nginx.

Порядок:

```text
приём потока → временный карантин → размер → расширение → libmagic MIME → сигнатура → ClamAV → MediaCMS/FFmpeg
```

При отсутствии libmagic или ClamAV проверка завершается отказом, а не разрешением.

## 5. AI

`AI_GATEWAY_URL` должен указывать на имя контейнера во внутренней Docker-сети. Не добавлять `ports:` для AI Gateway. Домашний узел сам забирает задания; VPS не подключается к открытому домашнему порту.

## 6. Проверка

- health всех контейнеров;
- `/api/v1/search?q=test&page=1`;
- `/api/v1/whoami` после входа;
- `/api/portal/home/`;
- создание AI-задачи авторизованным пользователем;
- 401 для гостя и 429 при превышении лимита;
- тестовые безопасные и запрещённые файлы;
- невозможность скачать файл из карантина;
- заголовки Caddy;
- вход по email, регистрация через Яндекс/ВК и возврат на `/`;
- восстановление из резервной копии в тестовой среде.

Только после этих проверок заменять production frontend или пересоздавать отдельный контейнер web.
