# Техническая архитектура безопасности для российского контура

## Статус

Это инженерная основа, встроенная по материалам комплексной документации «Журавли». Она **не является заключением о полном юридическом соответствии**: перед публичным запуском требуется проверить оператора, цели обработки, согласия, сроки хранения, уведомление Роскомнадзора, фактическое место баз данных и договоры с подрядчиками.

## Принцип системы

```text
Браузер
  ↓ HTTPS / CSRF / Secure cookie / rate limit
Caddy
  ↓ только внутренняя Docker-сеть
Django / MediaCMS
  ├─ PostgreSQL (без публичного порта)
  ├─ Redis (без публичного порта)
  ├─ карантин загрузок → MIME → сигнатура → ClamAV → FFmpeg
  ├─ журнал безопасности и согласий
  └─ AI Gateway (без публичного порта)
          ↓ домашний узел сам забирает задания
     koofstudio / локальная модель
```

## Что встроено

1. HTTPS, HSTS, CSP, `nosniff`, ограниченный `Permissions-Policy` и журнал Caddy.
2. Secure/HttpOnly cookies, CSRF trusted origins, ограниченный CORS.
3. Ограничение частоты AI-заданий через Redis/Django cache. Тем же способом следует ограничить входы, регистрацию, комментарии и загрузки.
4. Раздельные роли MediaCMS; спорные решения AI не выполняются автоматически.
5. Загрузка файла в карантин до публикации.
6. Проверка расширения, заявленного MIME, фактического MIME через libmagic, сигнатуры, размера и ClamAV.
7. Внутренний AI Gateway; домашний AI-узел не принимает публичные входящие соединения.
8. Секреты только в серверном `.env` с правами `0600`; во frontend и ZIP их нет.
9. Резервные копии базы, медиа, конфигурации и зашифрованных секретов; восстановление необходимо регулярно тестировать.
10. План инцидента: фиксация времени, изоляция, сохранение журналов, смена секретов, оценка затронутых данных и предусмотренные законом уведомления.

## Персональные данные и размещение

- PostgreSQL с учётными записями, профилями, согласиями, сессиями и журналом действий должен находиться в утверждённом российском контуре, если система собирает персональные данные граждан РФ и применимо требование локализации.
- Объектное хранилище с персональными файлами и резервные копии включаются в карту размещения данных.
- Аналитика и CDN не должны незаметно получать идентификаторы пользователей; до их подключения требуется отдельная проверка передачи данных.
- На домашний AI-узел передаётся минимальный файл или фрагмент и идентификатор задачи, а не полная пользовательская база.

## Официальные точки проверки

- Портал Роскомнадзора для уведомления об обработке персональных данных: `https://pd.rkn.gov.ru/operators-registry/notification/`
- Форма сообщения об инциденте: `https://pd.rkn.gov.ru/incidents/`
- Рекомендации Роскомнадзора по политике обработки ПД: `https://old.rkn.gov.ru/personal-data/p908/`
- Официальное опубликование правовых актов: `https://publication.pravo.gov.ru/`

Требования меняются. Перед запуском нужно сверить актуальную редакцию 152-ФЗ и связанные подзаконные акты на дату публикации.
